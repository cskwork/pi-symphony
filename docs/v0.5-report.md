# Symphony for Pi — v0.5 release report

## What shipped

Git worktrees and controlled delivery — delegated roles gain isolated write surfaces with fenced ownership:

- **Typed git mutations** (`src/worktrees.ts`) — every git mutation Symphony performs is a typed command object rendered to a fixed argv (`worktree_add/remove`, `branch_create`, `merge_ff_only`, `checkout_sha`). No UI, skill, or role can supply free-form git arguments; `isGitMutationArgv` lets the guard layer classify any mutation attempt.
- **Worktree registry** — allocation only after a preview, canonicalized paths forced *outside* the repository, duplicate-active-path rejection, deterministic sanitized collision-safe branch names (`sym/<task>/<slug>-<unique>`, never deleting/resetting existing branches), persisted registry with orphan tracking.
- **Fenced write leases** — atomic compare-and-swap with monotonically increasing fencing tokens: exactly one winner under concurrent acquisition; ownership transfer bumps the fence; stale reports (old token or moved head) are rejected before any gate accepts them.
- **Delivery safety** — non-mutating preflight reporting *each* blocker separately (approval, policy drift, stale evidence, dirty target, conflicts, missing evidence); `IntegratedUnverified` outcome when a mutation lands but checks fail — no auto-reset, no success label, operator disposition required; manual integration verification requires the result SHA to contain the approved task head or an explicit squash acknowledgment.
- **Cleanup safety** — worktree removal blocked by uncommitted changes, unknown untracked files, or active process use; no destructive fallback; orphaned worktrees are flagged for repair, never auto-deleted.

## Verification

251 tests across 27 files; tsc clean; smoke 5/5. The typed-command renderer and the read-only git allowlist (v0.1) together mean the only git mutations in the product are the five typed kinds above.

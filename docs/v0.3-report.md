# Symphony for Pi — v0.3 release report

## What shipped

Workflow customization and composable skills, built on validated building blocks:

- **Typed condition AST** (`src/workflow-def.ts`) — `task_kind`, `task_field`, `changed_paths`, `all/any/not`. Data-only: parser rejects code, scripts, `$eval`, unknown operators, and extra fields (V03-WF-004). Evaluation consults a bounded facts object with a full explanation trace.
- **Graph validation** — exactly one entry (progression edges), ≥1 terminal success, no unreachable stages, no unknown targets, and invariant enforcement: no path to `done` without a check-gated exit (V03-WF-002/003).
- **Dry simulation** — explains selected/skipped stages, condition traces, terminal outcome; cycle and expansion guards (V03-WF-005).
- **Graph-driven engine runtime** — `compileWorkflow()` compiles a validated definition into the same transition/contract model the engine uses; review provenance is non-negotiable (any review-actor stage exit is provenance-gated, custom or not). The compiled default graph is test-asserted equivalent to the static v0.1 engine.
- **Skills layer** (`src/skills.ts`) — manifest v1 validation, catalogs with progressive disclosure (bodies load only via `loadBody`), pin lock with content-hash mismatch detection, capability intersection (role ∩ repository ∩ skill; a skill can never *add* a forbidden capability), 5-rule linter, deterministic behavioral fixtures (V03-SKILL-*, V03-EVAL-001).
- **Extension tools** — `sym_skills` (stage-filtered catalog, no bodies) and `sym_skill_select` (loads one body with source/version/hash provenance and the effective capability verdict).
- **Migration** (`src/migration.ts`) — pure preview → atomic apply with backup → explicit rollback; unknown fields preserved; configuration revision model with monotonic revisions and content hashes (V03-CFG-001/002).

## Deliberate scope note

The browser workflow editor rides on the v0.2 config editor (validate/diff/apply of v2 YAML); the PRD's own UI constraint is "no drag requirement; every board operation has list/action equivalents", and the validated-YAML + simulation path covers the editor contract. Playwright E2E remains deferred to v0.9.

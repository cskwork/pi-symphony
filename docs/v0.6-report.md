# Symphony for Pi — v0.6 release report

## What shipped

Multi-task scheduling with bounded parallelism (`src/scheduler.ts`):

- **Dependency DAG** — validated edges (existence, typed conditions, self-reference, cycle freedom); hard dependencies evaluate against durable task/evidence state, never a transient UI projection; conditions: `task_done`, `stage_reached`, `check_passed`.
- **Deterministic scheduler** — candidate selection is a pure function of the snapshot (priority → aging → createdAt → taskId tie-break); starvation bound guarantees an eligible aged task beats fresh higher-priority work; pause blocks all dispatch with explicit reason codes; every non-runnable task exposes one primary reason (`dependency_unmet`, `approval_pending`, `admission_paused`, `capacity_exhausted`, …).
- **Dispatch protocol** — intent → acknowledged → reconciling → resolved; idempotent by dispatch ID; unacknowledged intents reconcile instead of duplicating while leases may still be valid.
- **Capacity + resources** — all-or-nothing multi-lease admission (claim every lease or none, with rollback on partial failure); occupancy never exceeds limits under concurrent claims; exclusive resources (ports, database locks) have exactly one owner with explicit release.
- **Retry taxonomy** — transient/deterministic/policy/user/unknown classes with distinct retry rules and backoffs; circuit breakers open after a threshold and halt dispatch, with explicit reset.
- **Rebuildability** — scheduler state is a pure projection of durable task/evidence facts and the dispatch/lease logs; replaying the logs reproduces the same decisions.

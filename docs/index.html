Pi 코딩 에이전트를 위한 증거 기반 개발 워크플로. 플랜·구현·독립 리뷰·결정론적 검증·통합까지 — 모든 단계가 검증 가능한 증거와 함께 기록되고, 모델은 그 게이트를 우회할 수 없습니다.

증거가 상태를 소유한다

에이전트가 "다 했어"라고 선언하는 것과, 검증 가능한 사실은 다릅니다. Symphony는 후자만 믿습니다.

🧭하나의 액션 워크플로

/sym continue 하나가 다음 유효 단계를 진행합니다. 플랜 브리프 주입, fresh 리뷰어 실행, 필수 체크 수행, 승인 요청 중 현재 상태에 맞는 것을 자동 선택.

🔍독립 리뷰

리뷰는 구현자 트랜스크립트를 절대 받지 않는 fresh 세션에서 실행됩니다. 읽기 전용 도구, 경계된 매니페스트, 턴 상한. 구현자 세션의 자체 리뷰는 엔진 차원에서 거부됩니다.

🔒우회 불가능한 게이트

실패·타임아웃·stale한 필수 체크는 Ready와 Done을 봉쇄합니다. 검증은 결정론적 증거 위에서만 판정되고, 모델 리포트가 이를 뒤집을 수 없습니다.

🛡️증거 무결성

체크 아티팩트는 sha256로 원장에 바인딩됩니다. 변조되면 broken으로 강등되어 게이트가 막힙니다. 작업 파일과 원장 불일치는 적발되어 보고됩니다.

🔄크래시 세이프 복구

어느 시점에서 죽어도 재시작은 진행 중 시도를 Interrupted로 표시합니다. 자동 재개 없음, 중복 실행 없음, 거짓 완료 없음. Resume과 Retry도 구분됩니다.

🌐동기화된 로컬 웹 UI

/sym web으로 loopback 전용 컨트롤 플레인을 띄웁니다. SSE 실시간 동기화, 설정 draft→diff→apply, 토큰 인증. 터미널과 브라우저가 같은 명령 서비스를 공유합니다.

워크플로

수동 통합을 제외한 모든 단계가 증거와 계약으로 게이트됩니다.

BACKLOG→ PLAN→ BUILD→ REVIEW→ VERIFY→ READY→ POST-VERIFY→ DONE
⛔
리뷰 provenance는 협상 불가구현자 세션이 제출한 리뷰는 절대 검증 게이트를 통과할 수 없습니다. fresh 리뷰어 세션 또는 기록된 인간 승인만 유효합니다.
⛔
changes_requested는 진짜로 막힌다리뷰어가 수정 요청을 내면 엔진이 review→verify 전환을 거부합니다. TUI가 아니라 엔진이 강제합니다.
⛔
커스텀 워크플로도 불변식을 지킨다v2 그래프로 스테이지를 자유롭게 추가해도, Done으로 가는 모든 경로에서 결정론적 검증과 완료 증거가 강제됩니다.
⛔
위임 역할은 읽기 전용scout·architect·security reviewer 등 위임 세션은 쓰기 도구를 가질 수 없습니다. 결과는 해시로 검증된 핸드오프로만 돌아옵니다.

설치 & 사용

저장소에 확장을 설치하고, 그 안에서 /sym으로 시작합니다. 프로젝트 스크립트는 실행되지 않습니다.

# 설치
pi install github:cskwork/pi-symphony

# 저장소 안에서
/sym init          # 체크 제안 확인 후 .symphony/ 생성
/sym new           # 인수기준 + 리스크로 작업 생성
/sym continue      # 다음 단계로
/sym web           # 브라우저 컨트롤 플레인

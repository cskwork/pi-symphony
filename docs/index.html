Symphony는 Pi 안에서 작업을 Plan → Build → Review → Verify → Ready → Done으로 끌고 가는 워크플로 엔진입니다. 각 단계는 검증 가능한 증거로만 통과되고, 그 게이트는 모델이 우회할 수 없습니다.

HOW IT WORKS

증거 기반 파이프라인

각 스테이지는 산출물(report)을 요구하고, 각 화살표는 계약(contract)을 검사합니다. 계약이 충족되지 않으면 엔진이 전환을 거부합니다 — 모델의 선언이 아니라 증거가 상태를 바꿉니다.

단일 변경 경로: 터미널과 브라우저 어디서 조작해도 모든 변경은 SymphonyCore 하나를 통과합니다. 상태는 마크다운 작업 파일 + 증거 아티팩트 + append-only 이벤트 원장에 기록되고, 어느 시점에서 죽어도 재시작이 그대로 복원합니다. 리뷰어는 fresh 세션으로 실행되어 구현자의 대화를 절대 받지 않습니다.

WALKTHROUGH

실제 사용 흐름

기억할 명령은 하나뿐입니다. /sym continue는 현재 상태를 보고 다음 유효 단계를 실행합니다.

1

초기화 /sym init

저장소를 읽고(스크립트 실행 없이) 체크 명령을 제안하고 .symphony/를 만듭니다. config.yaml은 커밋되고, evidence와 runtime은 gitignore됩니다.

제안 화면: .symphony/ ├── config.yaml 체크·정책 (커밋됨) ├── tasks/DEV-001.md 작업 = 사람이 읽는 마크다운 ├── evidence/DEV-001/ 체크·리뷰·통합 아티팩트 └── runtime/ 이벤트 원장·리스 (자동 복구)
2

작업 생성 /sym new

제목, 종류, 인수기준(acceptance criteria), 리스크를 입력합니다. 리스크를 선언하면 플랜 승인이 필수가 됩니다 — 플랜 도중 새 리스크가 발견되면 그때 승인이 요구됩니다.

3

진행 /sym continue

플랜 단계면 브리프를 주입하고, 빌드 단계면 구현 브리프를 주입하고, 리뷰 단계면 fresh 리뷰어를 띄우고, 검증 단계면 필수 체크를 실행합니다. 모델은 sym_plan_submit / sym_build_report로 구조화된 리포트만 제출합니다 — 전환은 엔진이 결정합니다.

4

독립 리뷰 FRESH SESSION

리뷰어는 새 Pi 세션에서 시작해 작업 계약·플랜·diff·리포트만 받습니다(구현자 트랜스크립트 제외). 도구는 읽기 전용, 턴 상한 존재. changes_requested를 내면 엔진이 다음 단계를 거부합니다 — TUI가 아니라 엔진이요.

5

검증과 통합 /sym complete

필수 체크가 현재 HEAD에서 통과해야 READY가 됩니다. 직접 머지한 뒤 통합 리비전을 기록하면, Symphony가 그 커밋이 타깃 브랜치에 있는지 확인하고 통합 리비전 기준으로 체크를 재실행합니다. 모두 통과해야 DONE입니다.

GUARANTEES

엔진이 강제하는 것들

이 규칙들은 문서가 아니라 코드입니다. 각 항목은 회귀 테스트로 고정되어 있습니다.

⛔
자기 리뷰 통과 불가 구현자 세션이 제출한 리뷰는 provenance에서 거부됩니다. fresh 리뷰어 세션 또는 기록된 인간 승인만 유효하고, changes_requested는 엔진이 실제로 막습니다.
⛔
실패한 체크 = 완료 봉쇄 실패·타임아웃·stale(다른 리비전에서 실행)·broken(아티팩트 변조) 체크는 READY와 DONE을 막습니다. 모델 리포트가 이를 뒤집을 수 없습니다.
⛔
증거 위조 감지 체크 아티팩트는 sha256로 이벤트 원장에 바인딩됩니다. 누군가 파일을 고쳐도 재시작 시 broken으로 강등되어 게이트가 막힙니다. 작업 파일과 원장의 불일치도 적발됩니다.
⛔
커스텀 워크플로도 안전 v2 그래프로 스테이지를 마음대로 추가해도, DONE으로 가는 모든 앞선 경로는 결정론적 검증 없이는 거부됩니다. 시큐리티 리뷰 스테이지 추가는 되도, 검증 우회는 안 됩니다.

🧭위임 = 읽기 전용

scout·architect·security reviewer 등 위임 역할은 쓰기 도구를 받지 못하고, 결과는 해시로 검증된 핸드오프로만 돌아옵니다.

🔄크래시 세이프

어느 시점에서 죽어도 재시작은 진행 중 시도를 Interrupted로 표시합니다. 자동 재개·중복 실행·거짓 완료가 없습니다.

🛡️사람 메모 보존

작업 파일의 관리 마커 밖에 쓴 인간 메모는 기계 쓰기가 반복돼도 바이트 단위로 보존됩니다.

INSTALL

한 줄 설치

Pi 0.84+ · Node 22+ · git 2.30+. 설치 후 어떤 저장소에서든 /sym으로 시작합니다.

# GitHub에서 설치
pi install github:cskwork/pi-symphony

# 저장소 안에서
/sym init      # 체크 제안 확인 → .symphony/ 생성
/sym new       # 인수기준 + 리스크로 작업 생성
/sym continue  # 다음 단계로 (기억할 명령은 이것 하나)
/sym web       # 브라우저 컨트롤 플레인 (loopback)
$pi install github:cskwork/pi-symphony클릭하여 복사

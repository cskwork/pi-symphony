# Symphony for Pi — v0.4 release report

## What shipped

Delegation, role topology, and durable handoffs — analysis concurrency without mutation concurrency:

- **Role sessions** (`src/roles.ts`) — immutable launch manifests (role, task, stage, attempt, revision, config hash, declared inputs, tools, skills, limits, *omitted scope*), lifecycle states (pending/running/completed/failed/interrupted/cancelled/superseded) with no resurrection from terminal states, hard+configured concurrency caps, restart recovery of lost sessions.
- **Single-writer guarantee** — `assertReadOnlyManifest` rejects write/edit/bash in any delegated role manifest at the host layer; the SDK runner launches with read-only tools and full isolation (`noExtensions/noSkills/noContextFiles`).
- **Topology presets** — Quick (1 role), Standard (scout + reviewer, 2 concurrent), Deep (5 roles incl. security reviewer + architect + QA analyst); every role has mandatory turn and wall-clock budgets.
- **Durable handoffs** — append-only audited ledger: submit (validated: sender≠recipient, task/stage/attempt, hex config hash, artifact refs *with sha256 digests*, summary ≤2000 chars), idempotency keys (retries return the same handoff), acceptance gated on role/task/stage/attempt/topology-snapshot match, complete/fail/supersede/expiry transitions, event replay rebuilds identical state.
- **SDK runner** — `DelegatedRoleRunner` generalizes the fresh reviewer to any role with the manifest's frozen context, turn cap fail-closed, structured output parsing.
- **Commands** — `/sym roles` (topology + sessions + single-writer note), `/sym delegate <role>` (manifest → launch → run → handoff submit/accept/complete), `/sym handoffs` (queue view).

## Design boundary (as specified)

Multiple role sessions, one write owner: delegated scouts/analysts/reviewers are read-only in v0.4; isolated write-capable worktrees arrive in v0.5.
